### [E-2026-11-21-030210-2f2d] 古兰经的中文重写成大白话，每章加「这一章在讲什么」导读

- **type**: fix
- **scope**: content/quran.json, translations/en/quran.json, scripts/build.mjs, scripts/content.mjs, scripts/import-dashboard.mjs, scripts/quran-add.mjs, src/styles.css, AGENTS.md
- **impact**: 用户看了古兰经第一版预览说「我想要的是白话文，我还是看不懂」。第一版中文贴着字面译（如 79:1「以那些猛力拔取的起誓」），不知道背景的人读不懂。现在 571 节中文全部重写：用平常说话的词，说清是谁在对谁说；原文没有、不补就看不懂的字放在圆括号里（79:1「我指着那些用力把（坏人的灵魂）拽出来的（天使）发誓」）。38 章每章经文前面多一段「这一章在讲什么」（英文版是 What this chapter says）。英文译文没动。
- **changed**: (1) 中文 571 节重写；每章第 1 节开头统一成「奉最仁慈、最慈爱的真主的名。」；「清算日」改叫「审判日」。12 条对照注跟着改（原来写「白话和英文都照字面译」的，改成「白话把最通行的说法放在括号里，英文照字面」）。全书三语对照总结加一段说明括号是什么。(2) 章可以带导读：面板书库的章和 content 的章多一个可选的 `intro`，英文导读在 translations/en 那一章的 `intro`（合并后是 `ch.enIntro`）；build.mjs 在栏目开关上方出 `<p class="ch-intro">`，多章书章节页的 description 有导读时用导读，没有才用「开头：第一段」。(3) quran-add.mjs 的译稿格式加 `! 中文导读`、`!= 英文导读` 两种行。(4) AGENTS.md 写明古兰经白话的标准。
- **ripples**: (1) 古兰经中文版圆括号里的字不是经文，是本站补的通行解释；以后补第 2–77 章要守同一个写法，否则前后两种口气。英文版不加括号。(2) `intro` 对所有书都能用，别的书现在都没有；给别的书加导读只要在面板书库的章上写 `intro`。(3) 多章书章节页的 description 生成规则变了（有导读用导读），目前只影响古兰经的 76 个页面。(4) 本机预览（scripts/serve.mjs）只在 content/、translations/、src/ 变动时重建，改了 scripts/build.mjs 要重启预览，否则它会用内存里的旧脚本把 dist 重建回旧样子。
- **verified**: `npm run check` 17 项测试通过，构建 430 页。合并脚本核对过：38 章、571 节每节都有新中文，12 条改写的注都对上了原来的词条。本机预览 /quran/79/ 用无头 Chrome 截图看过（500 宽深色）：导读块、括号里的补充、阿拉伯文都正常；/en/quran/79/ 有英文导读。重写后的中文没有逐节对着阿拉伯文让第二个人复核，也没有经穆斯林读者审过。
- **keywords**: 古兰经, 可兰经, 白话, 大白话, 看不懂, 括号, 导读, 这一章在讲什么, intro, ch-intro, enIntro, 审判日, quran-add
- **learned**: [rule] 用户说的「白话」是「完全没背景的人一遍看懂」，不是「用现代汉语逐字对译」：经书、法律、技术文档这类原文省略很多的东西，照字面译成现代汉语仍然看不懂；要把省掉的主语、对象、背景补出来（补的放括号，和原文分开），并在每章前面先用两三句讲这一章在说什么。动手译大批内容之前，先拿最难懂的一小段给用户看口气对不对。 [knowledge] 开着本机预览时改了构建脚本本身，要重启预览进程：监听文件变动的预览服务只重跑内存里已加载的旧 build 函数，会把刚用新脚本构建好的 dist 盖回旧样子，看起来像「改动没生效」。
