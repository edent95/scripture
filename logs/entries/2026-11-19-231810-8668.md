### [E-2026-11-19-231810-8668] 首页一键「继续读」、在读 / 读完了分开放;修 iPhone SE(375 宽)页头与书卡被裁

- **type**: feat
- **scope**: src/app.js, src/styles.css, scripts/build.mjs, tests/site.test.mjs
- **impact**: 用户要求三件事:一下回到之前读的地方;读过的书和没读过的放不同地方;iPhone SE2 上 PWA 被裁。现在首页标题下面有一颗「继续读 → 法华经 · 第 2 章 · 第 28/139 段」按钮(最近在读的那本);在读的书卡搬到最上面的「在读」(最近读的排前,点书卡也直接回到上次那一段),读完的搬到最下面的「读完了」,没读过的留在原来按传统分的组里。375 宽时页头不再挤成四行,栏目开关不再被页头盖住,首页书卡不再比屏幕宽。
- **changed**: (1) app.js 新增本机存储 `scripture.last.v1` { 书: { ch, v, t } }:章节页记「页头与栏目开关下面第一段还露着的经文」,滚动(300ms 节流)、带 #v 进来、或停留满 8 秒才记,只点开看一眼不记;旧的 `scripture.progress.v1`(读到过的最远一段)照旧,用来判断读完 / 读到一半。只有旧进度、没有 last 记录时,回到读到一半的那一章的最远一段。(2) build.mjs 首页加 `<a class="resume" data-resume hidden>` 和两个空的 `<section class="tradition shelf" data-shelf="reading|done" hidden>`,app.js 把 `<li>` 搬进去、把搬空的组藏起来、把 01/02… 编号按实际显示的组重排。(3) 裁切:用 CDP 按 375×667 实测,页头站名被挤成 4 行、页头 78px 而栏目开关写死贴在 64px(被盖住 14px);首页 `.book-list` 手机上是 `1fr`(最小宽度 auto),被长的罗马转写书名撑到 388px,右边被 `main { overflow-x: clip }` 切掉;英文版页头溢出把整页撑到 396px。改成:≤480px 收掉页头的「Eden ↗」(页脚还有)、站名缩小且 `text-wrap: balance`;app.js 把页头实际高度写进 `--header-h`,栏目开关 `top` 与 `.verse` 的 `scroll-margin-top` 跟着它;`.book-list` 用 `minmax(0, 1fr)`,长书名 `overflow-wrap: anywhere`;`.pager` 允许换行(320 宽时超出 4px)。
- **ripples**: (1) 首页书卡的 DOM 位置现在由 app.js 决定:以后给首页分组加东西(筛选、排序、计数)要考虑书卡会被搬到 `[data-shelf]` 里,分组编号也是 app.js 重写的,build.mjs 里写的 01/02 只是没有 JS 时的样子。(2) 没读完的书卡 href 会被 app.js 改成 `章/#v段`,多章书点卡不再进目录页(面包屑能回目录)。(3) 页头高度不要再写死 64px,用 `var(--header-h, 64px)`。(4) 页头再加按钮前先按 375 宽量:现在右边三颗(EN、中文、浅深色)加站名刚好一行。(5) 加第三种语言时 app.js 的 `L` 表(继续读 / 第 n 章 / 第 v/n 段)和 build.mjs 的 `T[lang].shelf*` 都要补。
- **verified**: `npm run check` 13 项测试通过、构建 352 页。CDP 模拟 375×667 与 320×568:首页、/lotus-sutra/、/lotus-sutra/2/、/en/、/en/heart-sutra/、/en/bhagavad-gita/、/upanishads/ 没有任何元素超出屏幕,页头 64px,栏目开关贴在 64px(改之前:首页 120 个元素超出、页头 78px、英文版整页 396px)。预置 localStorage 后首页显示「继续读 法华经 · 第 2 章 · 第 28/139 段 → /lotus-sutra/2/#v28」,分组为 01 在读 / 02 佛经 / 03 巴利文经典 / 04 印度经典 / 05 读完了;/diamond-sutra/ 滚到 3000px 后 last 记下的段号等于屏幕最上面那一段。真机(iPhone SE2 主屏幕打开)没测,要用户看。

- **learned**: [knowledge] 无界面 Chrome 的 `--window-size=375,667 --screenshot` 量不了手机版面:窗口最小宽度是 500,页面按 500 宽排版、截图只截左边 375,看起来像「右边被裁」其实是假象。要量手机宽度得走 CDP 的 Emulation.setDeviceMetricsOverride(mobile: true);Node 22 自带 WebSocket,不装 puppeteer 也能连(--remote-debugging-port=0,读 user-data-dir 里的 DevToolsActivePort)。 [knowledge] CSS grid 的 `1fr` 等于 `minmax(auto, 1fr)`,格子里有一个不能断行的长词就会把整列撑得比屏幕宽;外层若有 `overflow-x: clip`,不会出横向滚动条,只是右边静静被切掉。手机单列要写 `minmax(0, 1fr)`。
